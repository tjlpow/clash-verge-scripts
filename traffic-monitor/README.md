# Clash Verge 流量检测

本流程适用于当前 Mac 上的 Clash Verge。项目仓库是 https://github.com/tjlpow/clash-verge-scripts 。在没有既有对话背景时，先读取本目录的最新文件和仓库根目录的 `clash-verge.js`；以当前运行的 Clash 状态判断实际链路。

只手动触发，不设置定时任务。检测期间不切换模式、节点、配置，不重启 Clash，也不发送 Claude 消息。不要读取或上传 `Merge.yaml`、机场凭据、Claude 对话正文或令牌。

## 代码检测

1. **取得程序**：读取最新 `check.cjs` 和 `expected-routes.json`。本机没有可运行副本时，下载到 `~/Desktop/traffic-monitor/`；已有副本则核对并更新到仓库最新版本。
2. **采集连接**：告知用户开始 30 秒采样，然后运行 `node ~/Desktop/traffic-monitor/check.cjs --seconds 30`。用户可以在采样期间使用要检查的应用；没有产生目标流量就报告“证据不足”。
3. **核对结果**：程序只读 Clash 本地控制接口的 `/configs`、`/proxies`、`/rules`、`/connections`，以及本机 Claude IPv4 转发服务的可达性。按 `expected-routes.json` 比较命中规则与实际 `chains`。
4. **保存与答复**：每次在桌面保存一个 `clash-traffic-check-时间.json`，再按“统一输出”答复，并告知实际文件路径。本机程序副本若在本次创建或更新，也一并列出。

## 模型检测

每次都先执行上面的**代码检测**，取得同一次的新报告；用户无需另传报告。随后：

1. **核对证据**：读取报告、独立预期、仓库 `clash-verge.js` 和当前已加载规则。先确认模式、TUN、分组选择、采样量及规则优先级。未采到目标流量、采样期间切组或链路证据不完整时，保留“证据不足”。
2. **区分原因**：逐项判断规则遗漏、国内 AI 优先级、进程识别、`REJECT`／`Exit Off`、辅助进程、节点连接失败或短连接漏采。分组名称不能证明实际公网出口 IP。
3. **审查新域名**：用实际连接和服务官方网络文档核对。共享 CDN、监控、GitHub、npm 等域名不得仅凭一次出现就整体划入 Claude。
4. **提出建议**：只给出有证据的最小改法。每项标记“已证实／待实测／不建议修改”，写明现状、依据、可能影响及复测方法。检测本身不修改脚本；用户同时要求修复时，才修改脚本、独立预期和文档，并验证后提交。

模型结论只在对话中输出，不额外创建本地文件。

## 判定标准

- **优先级**：本地／私有地址与国内 AI 先于 Claude；Claude 专属域名、地址范围和可识别进程先于通用国外 AI；其余按实际规则顺序处理。
- **Claude 链路**：业务连接应经 `Claude IPv4 relay`；转发服务再按 `🧠 Claude` 与 `🌐 Claude Exit` 的当前选择建连。`Exit Off` 只用中转，`REJECT` 主动断流。转发、中转、出口是不同连接，观察到各段不等于逐请求精确关联。
- **其他流量**：国内 AI 直连；其他国外 AI 跟随 `🤖 AI`；Notion／GitHub 跟随 `🚀 main`；未命中流量跟随 `🐟 Fallback`。这些组的实际节点以运行时选择为准。
- **结论**：`PASS` 仅表示本次观察到的相关连接及链路段符合预期；`FAIL` 表示已发现规则或转发故障；`INCONCLUSIVE` 表示流量或证据不足。Clash `/connections` 只含采样时仍活动的连接，不能证明未出现的请求。

## 统一输出

代码检测的 JSON 固定包含 `status`、`environment`、`summary`、`claudeSegments`、`issues`、`observations`、`fallbackCandidates` 和 `limitations`。只记录域名、进程标签、命中规则与链路，不记录 URL 路径、正文、令牌或本机源地址。

两种检测在对话中均按以下五项答复：

1. **结论**：通过／异常／证据不足；写明检测时间与范围。
2. **当前状态**：Clash 模式、TUN、Claude 中转和出口、转发服务。
3. **链路证据**：目标域名／进程、命中规则、实际链路与预期链路。
4. **异常与遗漏**：严重程度、证据及待实测项；没有已证实异常时明确写出。
5. **下一步与本地文件**：复测或最小修改建议；列出桌面报告和本次创建／更新的程序文件路径。
