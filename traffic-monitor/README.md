# 流量检测

本目录只用于 macOS Clash Verge。代码检测读取本机控制接口，不读取对话内容，也不修改模式、节点、脚本或配置。Shadowrocket 没有接入这套本机连接采样。

## 两种手动检测

1. **代码检测**：在目标应用产生流量时，运行 `node traffic-monitor/check.cjs --seconds 30`。程序每 500 毫秒读取一次活动连接，并读取模式、TUN、分组选择和 Claude IPv4 转发服务状态。默认只把 JSON 报告输出到终端。
2. **模型检测**：把代码报告、`expected-routes.json` 和仓库当前的 `clash-verge.js` 交给模型。模型按下述流程复查异常与遗漏；没有报告时先做代码检测。两种检测都由用户在对话中手动触发。

需要保留报告时，先告知用户，再加 `--save`。程序仅在用户桌面生成一个 `clash-traffic-check-时间.json`，权限为 0600。若执行环境没有仓库文件，先告知用户需下载代码；本地副本默认放桌面。不要把报告、控制接口数据、机场凭据或 `Merge.yaml` 提交仓库。

## 判定边界

- **预期链路**：`expected-routes.json` 独立记录规则意图。本地／私有地址与国内 AI 规则先于 Claude 进程规则；Claude 官方域名和可识别的 Claude 进程经本机 relay；其他国外 AI、Notion／GitHub 和兜底分别跟随对应组。
- **实际链路**：以 Clash `/connections` 的目标域名、进程、命中规则和 `chains` 为证据；`chains` 通常由最终节点向上列组名。分组选择取实际运行值，不把节点名当成出口 IP 证明。
- **Claude 多段连接**：业务连接、中转和出口分别出现。报告 `claudeSegments` 仅说明采样期间是否观察到各段，不宣称逐请求精确关联。`Exit Off` 只需中转；`REJECT` 代表主动断流。缺少某段、没采到业务连接、采样期间切组或不在规则模式时，结论为 `INCONCLUSIVE`。
- **短连接**：Clash `/connections` 只有活动连接。采样没看到请求不等于规则正确。页面、插件、MCP 或 CLI 新功能需产生真实流量后再复查。
- **网络边界**：此检测不发送 Claude 消息，不测目标网站公网出口。要确认最后一跳的真实 IP，需另做目标网站回显测试。

## 标准结果

代码报告固定包含 `status`（`PASS`／`FAIL`／`INCONCLUSIVE`）、`environment`、`summary`、`claudeSegments`、`issues`、`observations`、`fallbackCandidates` 和 `limitations`。报告只保留域名、进程标签、规则与链路；不保留 URL 路径、请求正文、令牌或本机源地址。

对话中的代码检测和模型检测都按以下顺序答复：

1. **结论**：通过、异常或证据不足；说明检测时间与范围。
2. **当前状态**：Clash 模式、TUN、Claude 中转／出口、转发服务。
3. **链路证据**：目标域名／进程、命中规则、实际链路、预期链路。
4. **异常与遗漏**：逐项标明严重程度、证据和是否仍需实测；没有则写“未发现已证实异常”。
5. **下一步与本地文件**：需要的复测或最小规则修改；列出实际生成的文件路径，没有则写“无”。

## 模型复查步骤

1. **核对输入**：先确认报告时间、Clash 模式、采样量、分组是否变化。若 `INCONCLUSIVE`，先指出缺少哪段证据，不推断规则已覆盖全部请求。
2. **区分原因**：按脚本真实优先级判断是域名／进程未覆盖、国内 AI 优先级、分组选择、节点故障、UDP 拦截、辅助进程故障，还是采样遗漏。
3. **核对新域名**：参考官方网络要求、服务自己的文档或实际命中记录。共享 CDN、监控、GitHub、npm 等域名不能仅凭一次出现就整体划入 Claude。
4. **提出最小修改**：每项写清“原规则 → 建议规则 → 可能影响 → 验证方法”，标注 `已证实`、`待实测` 或 `不建议修改`。只有明确要求修复时才编辑脚本。
5. **回归**：若修改，检查国内 AI 直连、Claude relay／中转／出口、其他 AI、Notion／GitHub、Fallback、`Exit Off` 和 `REJECT`。新证据成立后同步更新独立预期，再用真实连接复测。
