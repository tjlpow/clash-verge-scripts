# 对话式流量检测流程

**适用范围**：当前 Mac 上的 Clash Verge。用户只在本对话回复数字；采样进程在本机后台运行，直到用户选择结束。不要因某条消息已经发完才开始采样。连接记录和报告放在系统对话临时目录，不写桌面，不设定时任务。

## 预载时读取的依据

- **项目现状**：阅读仓库根 [README 的 Clash Verge、策略组选项、Claude 出口选择和更新流程](../README.md)，以及 [clash-verge.js 顶部维护注释](../clash-verge.js)。它们说明现有规则、Claude 链路、辅助进程和迭代方式；此处不另复制一份规则清单。
- **本机权威脚本**：`~/Library/Application Support/io.github.clash-verge-rev.clash-verge-rev/profiles/Script.js`。核对其与仓库 `clash-verge.js` 的差异；本机 `Merge.yaml` 含凭据，不复制、展示或提交。按 `Script.js` 顶部注释执行修改、校验、提交及生效提示。
- **检测依据**：本目录的 `expected-routes.json` 是独立预期；`check.cjs` 只读 Clash 控制接口，并通过指定的本机代理入口探测公网 IPv4。预载时核对 Node 可用，将这两个文件的最新版放到系统临时目录 `clash-traffic-monitor/runner/`，检查语法。此阶段不启动采样。
- **运行边界**：不切换 Clash 模式或节点，不重启 Clash，不代替用户发送 Claude 消息，不读取对话正文或令牌。读取连接的域名、进程标签、命中规则、节点链和字节变化即可。

## 对话阶段与数字选项

### 预载

完成上述准备后，只回复操作指引：**“准备完成。回复 1 开始检测。”** 采样分析全部活跃连接，重点核对 Claude。

### 开始：用户回复 1

1. 在后台运行 `node <临时目录>/clash-traffic-monitor/runner/check.cjs start`。必须收到 `READY`，确认首次连接快照已经读取，才能回复用户。
2. 回复：**“采样已开始。请现在操作 Claude；完成后回复 1 结束检测。”** 此时不要结束对话里的后台采样。用户若询问进度，运行 `status` 读取状态。
3. 采样读取所有活跃连接的元数据；旧连接只有在采样期间上传或下载字节数增加才算本次活动。Clash 的 `/connections` 是快照，极短连接仍可能漏采。采样最长 60 分钟，超时自动结束并标记证据不足。

### 结束：用户回复 1

1. 运行 `node <临时目录>/clash-traffic-monitor/runner/check.cjs stop`，等待后台采样停止并完成代码分析。读取同一会话生成的 `report.json` 和 `report.md`。
2. 回复可点击的 `report.md` 本地文件链接，简短说明结论、Claude 活动连接数、是否观察到 relay／中转／出口，以及证据不足之处。报告文件只留在系统临时目录。
3. 给用户数字选项：**1 模型复检　2 重新检测　3 清除报告**。不要在代码分析后自动做模型复检。

### 模型复检：用户回复 1

1. 读取当前 `report.json`、`report.md`、独立预期、仓库脚本和本机已加载规则。复查规则优先级、分组选择、进程识别、新域名及共享服务。结合实际连接和服务官方文档区分规则遗漏、节点故障、`REJECT`／`Exit Off`、辅助进程问题与采样遗漏。
2. 仅将有证据的结论追加到**原 `report.md`** 的“模型复检”小节。每项标记“已证实／待实测／不建议修改”，写明依据、最小改法与复测方法。不得仅凭共享 CDN、监控或开发平台域名就整体划入 Claude。
3. 回复同一个报告链接与简短复检结论，给数字选项：**1 开始优化脚本　2 重新检测　3 清除报告**。

### 优化脚本：用户回复 1

按本机 `Script.js` 顶部维护注释和根 README 的更新流程执行：修改本机权威文件、校验、按需更新辅助进程、同步仓库 `clash-verge.js` 和文档并提交。由用户自行重启 Clash Verge；不代替用户切换模式或节点。除非用户另有要求，不修改 Shadowrocket。把修改及验证摘要追加到原报告，回复报告链接和结果，并给数字选项：**1 重新检测　2 清除报告**。若复检只有待实测项，先说明需要补什么证据，不凭猜测改规则。

### 重新检测与清除报告

- **重新检测**：直接执行“开始”阶段，创建新会话和新报告；旧报告仍在临时目录，直到用户选择清除。
- **清除报告**：运行 `node <临时目录>/clash-traffic-monitor/runner/check.cjs clear`，删除本流程产生的所有临时采样会话与报告。完成后告知旧链接已失效，回复 **“1 开始检测”**。保留 runner 程序，方便再次使用。

相同数字在不同阶段代表不同操作；以最近一次回复给用户的选项为准。模型复检始终使用刚结束的同一份报告，不重新采样。

## 代码判定与报告

`check.cjs` 读取当前模式、TUN、规则、分组选择、Claude 转发服务及 `/connections`。另通过本机 Claude 中转入口和出口入口，在开始时、每隔 60 秒及结束时请求 IPv4 回显，记录探测时间、中转选择、实际节点和公网 IPv4；`Exit Off` 时最终出口显示中转 IP，链式出口则分别显示两段 IP。回显探测只走指定代理入口，失败记为未知，不回退直连。报告包含采样起止时间、全部观察到的连接元数据、采样期间新建或字节数增加的连接、固定规则比较、链路段证据及公网 IPv4 探测记录。未观察到 Claude 请求活动、分组中途变化、链路段不全或采样中断时输出 `INCONCLUSIVE`，不宣称“全部正常”。发现直连泄漏或转发故障时输出 `FAIL`。

`report.md` 是用户查看和后续追加复检结果的同一份报告；`report.json` 保存结构化代码结果。中转 IP 稳定性只根据探测时刻判断；相同 IP 不能证明间隔内没有变化，也不能代替 Anthropic 端实际所见 IP。只记录元数据，不记录 URL 路径、请求正文、令牌或本机源地址。两份文件均位于系统临时目录，权限只允许当前用户读取；系统清理临时目录后链接也会失效。
